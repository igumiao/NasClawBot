# 影视文件整理规范

⚠️ **`directory_tree` 是递归工具，没有深度限制。** 对 `/影视` 这种大根目录调用会一次性返回整个媒体库的完整树状结构（可能几百上千条目），严重浪费 token。只在你知道目标范围很小（如单个下载目录）时才用它。扫描用 `list_directory`，检查存在用 `get_file_info`。

## 📁 分类目录结构

整理前先确保 `{root}` 下存在以下目录。用 **一次** `list_directory({root})` 即可查看所有子目录，缺失的再用 `create_directory` 创建。不要用 `get_file_info` 逐个检查（8 次调用太浪费）：

```
{root}/
├── 电影/       ← 单部电影
├── 剧集/       ← 多季多集电视剧
├── 动漫/       ← 动画番剧
├── 综艺/       ← 综艺节目
├── 纪录片/     ← 纪录片
├── 其他/       ← 无法识别的资源，留待人工
├── 未整理/     ← 待处理的原始文件（唯一扫描来源）
└── trash/      ← 空目录和废弃文件，用户手动清理
```

---

## 🎬 电影（单层结构）

> 动画电影（动漫剧场版、动画长片）归入 **动漫**，不在此分类。

| 层级 | 格式 | 示例 |
|------|------|------|
| 文件夹 | `中文名.EnglishName.年份` | `黑客帝国.The.Matrix.1999` |
| 文件 | `中文名.EnglishName.年份.扩展名` | `黑客帝国.The.Matrix.1999.mkv` |

文件夹内字幕、nfo 等附属文件统一使用相同前缀。

---

## 📺 剧集/动漫/综艺/纪录片（三层结构）

| 层级 | 格式 | 示例 |
|------|------|------|
| 祖父级 | `中文名.EnglishName.年份` | `绝命毒师.Breaking.Bad.2008` |
| 父级 | `Season XX`（两位数字） | `Season 01` |
| 文件 | `中文名.EnglishName.SXXEXX.扩展名` | `绝命毒师.Breaking.Bad.S01E01.mkv` |

- 季度文件夹固定英文 `Season 01` / `Season 02` …
- 集数格式 `S01E01` 或 `S01.E01` 均可
- 单季资源同样用此结构（仍有 Season 01 层）

---

## 📋 整理流程

0. **初始化** — 用 `list_directory({root})` 一次查看 root 下已有目录，缺失的分类目录用 `create_directory` 创建。不要逐个 `get_file_info`。

1. **扫描** — 用 `list_directory` 查看 `未整理/` 的内容。`list_directory` 只列单层，不会递归展开整个媒体库。
   - 如果 `未整理/` 下的某个条目本身是目录（如一个下载包），再用 `list_directory` 或 `directory_tree`（仅在目录内容不多时）查看其内部结构
   - 不要对整个 `{root}` 调用 `directory_tree` —— 它会把已整理好的所有电影/剧集目录全部展开

2. **识别** — 从文件名提取：中英文名、年份（`19xx/20xx`）、季号（`S01`、`Season 1`）、集号（`E01`）

3. **判断类型**：
   - 有季/集标记 → 据内容归入 剧集/动漫/综艺/纪录片
   - 动画电影（动漫剧场版、动画长片）→ **动漫**，即使无季/集标记也不归入电影
   - 其他无季/集 → 电影
   - 不确定 → 用 TMDB 搜索辅助
   - **TMDB 查不到明确结果时**，按以下顺序尝试获取信息：
     1. **Tavily 网络搜索** — 用 `tavily_search` 搜索该影视作品的中英文名、年份、类型等信息。可分别用中文和英文关键词搜索以交叉验证。
     2. **LLM 自有知识** — 如果 Tavily 也查不到明确结果，可以依赖你（LLM）对该影视作品的训练知识来推断正确的中文名、英文名、年份和分类。
     3. **以上都失败** — 不论有无季/集标记，一律移入 `其他/` 待人工处理。
        原则是「查无实据就存疑」——宁可放 `其他/`，也不自作主张放入 电影/剧集/动漫 等已整理目录。

4. **创建结构** — 在对应分类目录下创建规范的文件夹和 Season 目录

5. **移动前检查上传状态** — 在执行 `move_file` 之前：
   - 用 `qb_get_torrent` 查找对应的种子（通过 `qb_hash` 参数），检查其状态是否为 `uploading` 或 `seeding`（即种子正在做种上传）
   - 如果种子正在上传（qb 会锁住文件导致移动失败），先用 `qb_control_torrent` 执行 `pause` 暂停种子
   - 暂停成功后再执行文件移动
   - **注意**：只允许 `pause` 操作，不要执行 `delete`、`resume` 等其他操作

6. **重命名并移动** — `move_file` 将文件移入新位置并改名
   - 移动前用 `get_file_info` 确认源文件存在
   - 移动后用 `get_file_info` 确认文件已到达目标位置

7. **清理** — 原位置空目录移入 `trash/`

## ⚠️ 要点

- 只处理 `未整理/`，不碰已整理好的目录
- 优先用 `tmdb_search` / `tmdb_details` 获取准确命名，不要猜
- TMDB 查不到时，用 `tavily_search` 网络搜索；网络也查不到时，可用 LLM 自有知识判断
- **TMDB + Tavily + LLM 知识都查不到的资源 = 存疑，放 `其他/`。禁止默认当成电影或剧集直接整理。**
- **注意 token 消耗**：`directory_tree` 递归无深度限制，对大目录调用会返回海量数据。扫描用 `list_directory`，检查存在用 `get_file_info`，搜索用 `search_files` + 精确 pattern。
