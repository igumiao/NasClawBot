# Agent Architecture Design

> Legacy LangGraph-era design. The active replacement design is [HelloAgents Runtime Architecture](helloagents-runtime-architecture.md). Keep this document as historical context for ADR 001.

## Overview

NasClawBot Agent 是一个基于 LangGraph 的单 Agent + 多 Tool 系统。主图负责意图路由、记忆加载、中断恢复，子图负责具体领域的任务执行。每个子图有独立的工具白名单。

## State Schema

### AgentState

```python
from typing import TypedDict, Literal
from dataclasses import dataclass


class Message(TypedDict):
    role: Literal["user", "assistant", "system"]
    content: str


class MediaRequest(TypedDict):
    title: str | None
    year: int | None
    media_type: Literal["movie", "tv", "anime", "variety", "documentary", "unknown"] | None
    season: int | None
    quality: str | None
    region: str | None
    extra_notes: str | None  # "不太恐怖", "适合周末" 等模糊偏好


class MediaCandidate(TypedDict):
    candidate_id: str
    source: Literal["tmdb", "mteam", "emby"]
    title: str
    year: int | None
    media_type: str | None
    match_score: float
    detail: dict  # source-specific payload


class MediaState(TypedDict):
    request: MediaRequest | None
    candidates: list[MediaCandidate]
    selected: MediaCandidate | None
    disambiguation_question: str | None


class PendingUserInput(TypedDict):
    type: Literal["disambiguation", "confirmation", "missing_info"]
    context: dict  # state needed to resume after user responds
    question: str
    options: list[dict] | None  # for disambiguation: list of candidate summaries


class ConfirmationState(TypedDict):
    payload: dict | None  # what the user needs to confirm
    user_decision: Literal["approved", "rejected", "pending"] | None


class ToolCallRecord(TypedDict):
    tool_name: str
    input: dict
    output: dict | None
    error: str | None
    duration_ms: int
    timestamp: str


class ErrorState(TypedDict):
    code: str
    message: str
    recoverable: bool
    retry_count: int


# --- Domain sub-states ---

class DownloadState(TypedDict):
    torrent_id: str | None
    download_url: str | None
    status: Literal["pending", "downloading", "paused", "completed", "failed"] | None
    qb_hash: str | None


class OrganizeState(TypedDict):
    scan_results: list[dict] | None
    plan: dict | None  # generated by generate_organize_plan
    plan_id: str | None
    status: Literal["scanning", "plan_generated", "confirmed", "executing", "done"] | None


class SubscribeState(TypedDict):
    media_title: str | None
    media_type: str | None
    rule: dict | None
    subscription_id: str | None


class RecommendState(TypedDict):
    user_profile: dict | None
    similar_media: list[dict] | None
    recommendations: list[dict] | None
    reasoning: str | None


class LibraryQueryState(TypedDict):
    query_type: Literal["exists", "detail", "stats", "missing"] | None
    results: list[dict] | None


# --- Top-level AgentState ---

class AgentState(TypedDict):
    # session
    user_id: str
    conversation_id: str
    request_id: str

    # conversation
    user_message: str
    messages: list[Message]
    response_to_user: str | None

    # routing
    intent: str | None
    current_workflow: str | None
    current_node: str | None
    workflow_status: Literal["in_progress", "awaiting_user", "completed", "error"]

    # memory
    memory_context: MemoryContext | None

    # shared media resolution
    media: MediaState

    # domain states (only one active per invocation)
    download: DownloadState | None
    organize: OrganizeState | None
    subscribe: SubscribeState | None
    recommend: RecommendState | None
    library_query: LibraryQueryState | None

    # interruption / human-in-the-loop
    pending_input: PendingUserInput | None
    confirmation: ConfirmationState | None

    # observability
    tool_trace: list[ToolCallRecord]

    # result / error
    final_result: dict | None
    error: ErrorState | None
```

### MemoryContext

```python
class PreferenceRule(TypedDict):
    key: str
    value: str
    strength: float       # 0.0-1.0
    confidence: float     # 0.0-1.0
    source: Literal["explicit", "behavior", "inferred"]


class AvoidanceRule(TypedDict):
    target_type: str      # genre, keyword, etc.
    target_value: str
    rule_level: Literal["hard", "soft"]
    reason: str | None
    confidence: float


class QualityPreferences(TypedDict):
    preferred_resolution: list[str]    # ["1080p", "4K"]
    preferred_source: list[str]        # ["M-Team"]
    subtitle_required: bool
    max_size_gb: float | None
    prefer_complete_season: bool | None


class HistorySummary(TypedDict):
    event_type: str
    summary: str
    created_at: str
    relevance_score: float


class SubscriptionSummary(TypedDict):
    title: str
    media_type: Literal["movie", "tv"]
    status: str
    rule_summary: str | None


class WatchContext(TypedDict):
    context_type: Literal["alone", "family", "friends", "dinner", "weekend", "unknown"]
    summary: str | None


class MemoryContext(TypedDict):
    profile_summary: str | None
    preference_rules: list[PreferenceRule]
    avoidance_rules: list[AvoidanceRule]
    quality_preferences: QualityPreferences | None
    workflow_preferences: dict | None
    relevant_history: list[HistorySummary]
    active_subscriptions: list[SubscriptionSummary]
    watch_context: WatchContext | None
    retrieval_reason: str | None
```

**MemoryContext 约束**:
- 不放完整聊天记录、完整下载历史、完整观看历史
- 不放所有订阅（只放活跃的）、所有偏好原始表
- 不放在数据库主键、工具调用历史
- MemoryContext 是压缩后的工作上下文，不是第二个大 State

## Subgraph Architecture

### Main Graph

```
                         ┌─────────────────────┐
                         │       START          │
                         └─────────┬────────────┘
                                   │
                                   ▼
                         ┌─────────────────────┐
                         │  has_pending_input?  │
                         └─────┬──────────┬─────┘
                            yes│          │no

                    ┌──────────────┐  ┌──────────────┐
                    │handle_pending │  │ load_context  │
                    │   _input      │  │ (Memory Router)│
                    └──────┬───────┘  └──────┬───────┘
                           │                 │
                           ▼                 ▼
                    ┌──────────────┐  ┌──────────────┐
                    │   resume_    │  │  classify_    │
                    │   workflow   │  │   intent      │

                           └────────┬────────┘

              ┌──────────────────────┼──────────────────────┐
              │                      │                      │
              ▼                      ▼                      ▼
    ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
    │ search_download  │   │   recommend      │   │    organize      │
    │    subgraph      │   │   subgraph       │   │    subgraph      │
    └────────┬────────┘   └────────┬────────┘   └────────┬────────┘

              └──────────────────────┼──────────────────────┘

                                     ▼
                           ┌─────────────────────┐
                           │   final_response     │
                           └──────────┬──────────┘
                                      │
                                      ▼
                           ┌─────────────────────┐
                           │        END           │
                           └─────────────────────┘
```

**主图职责**（只保留路由和协调）:
1. 中断判断 → `has_pending_input?`
2. 记忆加载 → `load_context` (Memory Router)
3. 意图识别 → `classify_intent`
4. 路由 → `route_to_subgraph`
5. 全局错误处理
6. 最终响应整理 → `final_response`

### Subgraph Types

#### Type A: Fixed-Flow Subgraph

用于下载、整理、订阅、查询等步骤明确的任务：

```
parse_request → query_local → query_external → generate_candidates → await_confirmation → execute
```

LLM 只在节点内部负责抽取、排序、生成解释，不决定流程顺序。

#### Type B: Agent Loop Subgraph

用于推荐、复杂查询等需要动态组合工具的任务：

```
planner → tool_call → observe → 是否完成?
                                    ├─ 否 → planner
                                    └─ 是 → final_response
```

Agent Loop 限制：
- 最多 5 轮 tool call
- 只能调用本子图工具白名单内的工具
- 每轮 tool call 后 observe 节点判断是否需要中断（消歧/确认/缺字段）

### Subgraph → Tool Whitelist Mapping

| Subgraph | Available Tools |
|----------|----------------|
| `search_download` | `search_emby_library`, `search_tmdb`, `get_media_detail`, `search_download_source`, `create_download_task`, `get_download_status` |
| `recommend` | `search_emby_library`, `search_tmdb`, `find_similar_media`, `get_user_watch_profile`, `rank_media_candidates`, `check_library_availability` |
| `organize` | `scan_unorganized_files`, `identify_media_files`, `generate_organize_plan`, `apply_organize_plan`, `search_tmdb`, `refresh_emby_library` |
| `subscribe` | `search_tmdb`, `get_media_detail`, `create_subscription`, `list_subscriptions`, `cancel_subscription`, `check_subscription_status` |
| `query_library` | `search_emby_library`, `get_emby_item_detail`, `get_emby_library_stats`, `check_emby_missing_episodes` |

### Candidate Resolver Node

独立节点，被各个子图复用：

```
search_results → candidate_resolver
                    │
                    ├─ 唯一高置信候选 → 直接设置 selected_candidate
                    │
                    └─ 需要消歧 → 设置 pending_input (type=disambiguation)
                                   → 发送澄清问题给用户
```

**判断逻辑**:

第一层（规则）：
- Top 1 vs Top 2 分数差距 < 0.15 → 触发消歧
- 多个候选标题近似相同（如"老男孩"/"Oldboy"） → 触发消歧
- 候选跨媒体类型（电影 vs 剧集） → 触发消歧

第二层（LLM Judge）：
- 规则通过后，LLM 判断是否可安全选择唯一候选
- 若不能，生成简短澄清问题
- LLM 只能决定"是否提问"和"怎么问"，不能绕过规则层的安全约束

## Tool Registry

### Tool Definition

使用 LangChain `@tool` 装饰器 + Pydantic args_schema：

```python
from langchain_core.tools import tool
from pydantic import BaseModel, Field


class SearchTMDBInput(BaseModel):
    query: str = Field(description="搜索关键词，如片名")
    year: int | None = Field(default=None, description="年份过滤")
    media_type: str | None = Field(default=None, description="movie | tv | person")


@tool(args_schema=SearchTMDBInput)
def search_tmdb(query: str, year: int | None = None, media_type: str | None = None) -> list[dict]:
    """搜索 TMDB 影视数据库，返回匹配的媒体条目列表。"""
    ...
```

### Tool Registry

```python
class ToolRegistry:
    """管理所有工具，支持按子图查询白名单。"""

    _tools: dict[str, BaseTool]
    _whitelists: dict[str, set[str]]

    def register(self, tool: BaseTool) -> None: ...
    def get_for_subgraph(self, subgraph: str) -> list[BaseTool]: ...
    def set_whitelist(self, subgraph: str, tool_names: set[str]) -> None: ...
```

子图编译时从 Registry 获取白名单工具：

```python
subgraph_tools = registry.get_for_subgraph("recommend")
recommend_graph = build_recommend_subgraph(subgraph_tools)
```

## Interruption & Recovery Flow

### 中断类型

| 类型 | 触发条件 | pending_input.type |
|------|---------|-------------------|
| 消歧 | candidate_resolver 判断多个候选 | `disambiguation` |
| 确认 | 下载/整理计划需要用户确认 | `confirmation` |
| 缺字段 | 媒体请求关键字段缺失 | `missing_info` |

### 中断流程

```
子图执行中 → 检测到需要用户输入
  ↓
设置 state.pending_input = {
    type: "disambiguation",
    context: {保存当前子图状态, 候选列表},
    question: "你说的是韩国版还是美国版？",
    options: [...]
}
  ↓
state.workflow_status = "awaiting_user"
  ↓
final_response 节点将 question 返回给 Web UI
  ↓
[用户回复] "韩国那个"
  ↓
主图入口 → has_pending_input? → yes
  ↓
handle_pending_input:
  - 根据 pending_input.type 路由到对应处理
  - disambiguation → candidate_resolver (映射用户回答到具体候选)
  - confirmation → 检查用户决定
  - missing_info → 补全字段合并回 media.request
  ↓
设置 state.selected_candidate，清除 pending_input
  ↓
resume_workflow → 回到原 subgraph 继续执行
```

**关键设计**：
- `pending_input.context` 保存恢复所需的所有状态，不依赖外部存储
- 用户回答后**不重新搜索**，而是将回答映射到已有的候选列表
- 主图的 `resume_workflow` 根据 `current_workflow` 和 `current_node` 决定从哪继续

## Memory Router

### 职责

根据当前 intent 动态构造 MemoryContext，不同 intent 加载不同内容：

| Intent | 加载内容 |
|--------|---------|
| `search_download` | quality_preferences, avoidance_rules, active_subscriptions |
| `recommend` | profile_summary, preference_rules, avoidance_rules, relevant_history, watch_context |
| `organize` | workflow_preferences, relevant_history (organize 相关) |
| `subscribe` | active_subscriptions, quality_preferences |
| `query_library` | 最小化 — 通常只需要 profile_summary |

### 流程

```
load_context node:
  1. 获取 intent
  2. 查询结构化偏好表 → preference_rules, avoidance_rules, quality_preferences
  3. 查询行为事件表 → relevant_history (按 relevance 过滤, 最多 5 条)
  4. 查询订阅表 → active_subscriptions (仅活跃的)
  5. 检测 watch_context (时间、节假日等推断)
  6. 组装 MemoryContext, 设置 retrieval_reason
  7. 写入 state.memory_context
```

### 存储表设计

```sql
-- 结构化偏好
CREATE TABLE user_preferences (
    user_id TEXT,
    key TEXT,
    value TEXT,
    strength REAL DEFAULT 0.5,
    confidence REAL DEFAULT 0.5,
    source TEXT DEFAULT 'explicit',  -- explicit | behavior | inferred
    updated_at TEXT,
    PRIMARY KEY (user_id, key)
);

-- 行为事件
CREATE TABLE behavior_events (
    id INTEGER PRIMARY KEY,
    user_id TEXT,
    event_type TEXT,       -- search, download, watch, rate, skip, subscribe
    payload JSON,
    created_at TEXT DEFAULT (datetime('now'))
);

-- 订阅
CREATE TABLE subscriptions (
    id INTEGER PRIMARY KEY,
    user_id TEXT,
    title TEXT,
    media_type TEXT,
    tmdb_id INTEGER,
    status TEXT DEFAULT 'active',  -- active | paused | completed
    rule JSON,
    created_at TEXT DEFAULT (datetime('now'))
);
```

## Tool Design Principles

### 只读工具：细粒度

Agent 可自主决定调用顺序和组合。

```
search_emby_library(query, media_type?)   → Emby /Items API
search_tmdb(query, year?, media_type?)    → TMDB Search API
get_media_detail(source, id)              → TMDB/Emby detail
search_download_source(keyword, filters?) → M-Team search
get_download_status(task_id)              → qBittorrent status
find_similar_media(tmdb_id)              → TMDB Recommendations API
get_user_watch_profile()                  → Memory Router
check_library_availability(items)         → Emby query
rank_media_candidates(candidates, prefs)  → LLM ranking
scan_unorganized_files(root?)             → File system scan
```

### 写入工具：粗粒度

封装事务边界、确认和日志。

```
create_download_task(candidate_id)        → M-Team token + qB add (paused)
generate_organize_plan(files)             → 生成整理计划，不执行
apply_organize_plan(plan_id)              → 按已确认的计划执行
create_subscription(media_id, rule)       → 创建订阅记录
cancel_subscription(subscription_id)      → 取消订阅
refresh_emby_library()                    → 触发 Emby 库刷新
```

## V1 Scope: Subgraph Implementation Order

1. **search_download** — 封装当前 workflow（风险最低，已有代码）
2. **query_library** — Emby 只读查询（验证 Emby API 可行性）
3. **recommend** — TMDB 推荐 + 本地库交叉查询
4. **subscribe** — 简单轮询订阅
5. **organize** — 文件检测报告（不执行自动移动）
